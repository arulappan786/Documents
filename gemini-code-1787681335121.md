### Debugging Request: Validation Rule Functions Executed Twice in Single Call Chain

#### Problem Description
We are encountering an issue where validation functions invoked via validation rules are executing **twice** during a single workflow/request lifecycle.

For example, when `CreateInvoiceMessageChangeRequests` is triggered within a validation rule:
1. **First Execution:** Successfully processes and creates the change request.
2. **Second Execution (within the same chain):** Fails because a pending change request already exists (created by the first run).

This duplicate invocation affects **all validation functions** attached to our validation rules, not just `CreateInvoiceMessageChangeRequests`.

---

#### Objectives
1. **Trace the Execution Flow:** Analyze the codebase to map how validation rules and their associated functions are resolved and executed during the request lifecycle.
2. **Identify the Root Cause:** Determine why the validation pipeline triggers twice in the same call chain. Look out for:
   - Duplicate event listeners, hooks, or lifecycle handlers (e.g., pre-save/post-save or interceptors).
   - Middleware or pipeline stages executing the validation suite multiple times.
   - Recursive or redundant calls within the validation engine / orchestrator.
   - Double-binding, multiple dependency injection registrations, or duplicate rule configuration evaluation.
3. **Recommend a Fix:** Provide a clean, idiomatic solution to ensure validation functions execute exactly once per call chain, along with any necessary safeguards (e.g., idempotency considerations).

---

#### What I Need From You
- A step-by-step trace of the duplicate invocation path through the relevant files.
- The exact file(s) and line(s) causing the redundant execution.
- Code diffs or refactored snippets demonstrating how to eliminate the second invocation.
